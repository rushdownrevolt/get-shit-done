Create `learn/lib/terminal.cjs` with:
- COLORS object: reset, bold, dim, underline, red, green, yellow, blue, magenta, cyan, white (raw ANSI escape codes)
- `useColor` constant: true only when `process.stdout.isTTY && !process.env.NO_COLOR`
- `style(text, ...styles)`: wraps text in ANSI codes, returns plain text when useColor is false
- `clearScreen()`: returns '\x1b[2J\x1b[H'
- `horizontalRule(width)`: returns dim-styled string of '─' characters (default to `process.stdout.columns || 80`)
- `highlightJS(code)`: simple keyword-only syntax highlighting using regex replace for JS keywords (cyan), strings (green), comments (dim). Returns unmodified code when useColor is false.

Follow GSD conventions: 'use strict', CommonJS, 2-space indent, single quotes, module.exports at bottom.
Match the code examples from 01-RESEARCH.md (ANSI Terminal Utility Module and Simple Syntax Highlighting sections).

Create `learn/lib/progress.cjs` with:
- `PROGRESS_PATH = path.join('.planning', 'learn', 'progress.json')`
- `DEFAULT_PROGRESS = { version: 1, currentModule: null, currentLesson: 0, modules: {} }`
- `loadProgress(cwd)`: reads progress JSON, returns parsed object. On any error (missing file, invalid JSON, missing fields), returns a copy of DEFAULT_PROGRESS. Always ensure returned object has all required fields (merge with defaults).
- `saveProgress(cwd, progress)`: writes progress JSON with `fs.writeFileSync`. Creates directory with `fs.mkdirSync({ recursive: true })`.

Match the code example from 01-RESEARCH.md (Progress File with Atomic Writes section).

Tests use `node:test` + `node:assert`. For progress tests, use temp directories (fs.mkdtempSync) with cleanup in afterEach. For terminal tests, test the string output of style() and highlightJS() directly -- these are pure functions.

Note: terminal tests should test the function output strings directly rather than trying to mock process.stdout.isTTY. Export useColor as a getter or test with explicit color mode parameter if needed for NO_COLOR testing.
