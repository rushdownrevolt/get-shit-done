# Phase 02.1: Add command 'c' to copy current lesson to clipboard - Research

**Researched:** 2026-03-12
**Domain:** Node.js clipboard integration, ANSI stripping, markdown formatting
**Confidence:** HIGH

## Summary

This phase adds a single-key `c` command to the existing lesson navigator that copies the current lesson content to the system clipboard in LLM-friendly markdown format. The implementation touches four areas: (1) adding a `c` key handler to `waitForKey()` and `runNavigationLoop()` in navigator.cjs, (2) creating a clipboard utility module using native OS commands via `child_process`, (3) building a markdown formatter that converts the lesson data object into clean markdown (stripping ANSI, adding context preamble), and (4) updating the navigation footer in renderer.cjs.

The codebase is small, well-structured CommonJS with zero dependencies. All patterns are established: keypress handling via readline, pure-function rendering, and `child_process` for OS interaction. The lesson data structure is a JSON object with typed content sections (`text`, `code`, `project`), which maps cleanly to markdown.

**Primary recommendation:** Create two new modules -- `clipboard.cjs` (OS clipboard write with fallback) and `clipboard-formatter.cjs` (lesson-to-markdown conversion) -- then integrate via three small changes to navigator.cjs and renderer.cjs.

### Pattern 1: Clipboard Write with Fallback
**What:** Try OS clipboard command; on failure, write temp file and open it
**When to use:** Every 'c' keypress
**Example:**
```javascript
// clipboard.cjs
'use strict';

const { execSync, exec } = require('child_process');
const fs = require('fs');
const path = require('path');
const os = require('os');

function getClipboardCommand() {
  switch (process.platform) {
    case 'win32': return 'clip';
    case 'darwin': return 'pbcopy';
    default: return 'xclip -selection clipboard';
  }
}

function copyToClipboard(text) {
  const cmd = getClipboardCommand();
  try {
    execSync(cmd, { input: text, stdio: ['pipe', 'pipe', 'pipe'] });
    return { success: true };
  } catch (err) {
    return fallbackToFile(text);
  }
}

function fallbackToFile(text) {
  const tmpFile = path.join(os.tmpdir(), 'gsd-lesson-' + Date.now() + '.md');
  fs.writeFileSync(tmpFile, text, 'utf-8');
  // Open the file with default editor/viewer
  const openCmd = process.platform === 'win32' ? 'start ""'
    : process.platform === 'darwin' ? 'open'
    : 'xdg-open';
  exec(openCmd + ' "' + tmpFile + '"');
  return { success: false, fallbackPath: tmpFile };
}

module.exports = { copyToClipboard, getClipboardCommand, fallbackToFile };
```

### Pattern 2: Markdown Formatter (Pure Function)
**What:** Convert lesson data object to LLM-friendly markdown string
**When to use:** Called before clipboard write
**Example:**
```javascript
// clipboard-formatter.cjs
'use strict';

function formatLessonForClipboard(lesson, currentIndex, totalLessons) {
  const parts = [];

  // Context preamble
  parts.push('> This is a lesson from GSD Learn, a terminal-based learning tool');
  parts.push('> that teaches how the GSD (Get Shit Done) CLI toolkit works.');
  parts.push('> Lesson ' + (currentIndex + 1) + ' of ' + totalLessons + '.');
  parts.push('');

  // Title
  parts.push('# ' + lesson.title);
  parts.push('');

  // Objective
  parts.push('## Objective');
  parts.push(lesson.objective);
  parts.push('');

  // Content sections
  for (const section of lesson.content) {
    if (section.type === 'text') {
      parts.push(section.value);
      parts.push('');
    } else if (section.type === 'code') {
      if (section.source) {
        parts.push('// ' + section.source.file + ':' + (section.source.startLine || 1));
      }
      parts.push('```' + (section.language || 'javascript'));
      parts.push(section.value);
      parts.push('```');
      parts.push('');
    } else if (section.type === 'project') {
      parts.push('## Your Mission');
      parts.push(section.task);
      parts.push('');
      if (section.deliverables && section.deliverables.length > 0) {
        parts.push('### Deliverables');
        section.deliverables.forEach((d, i) => {
          parts.push((i + 1) + '. ' + d);
        });
        parts.push('');
      }
    }
  }

  // Concept map
  if (lesson.conceptMap) {
    const { CONCEPT_MAP } = require('./concept-map.cjs');
    parts.push('## Architecture Overview');
    parts.push('```');
    parts.push(CONCEPT_MAP.trim());
    parts.push('```');
    parts.push('');
  }

  // Success criteria
  parts.push("## You'll know you've got it when:");
  parts.push(lesson.successCriteria);
  parts.push('');

  return parts.join('\n');
}

module.exports = { formatLessonForClipboard };
```

### Pattern 3: Flash Message in Navigation Loop
**What:** Show temporary feedback, then re-render lesson
**When to use:** After successful clipboard copy
**Example:**
```javascript
// In navigator.cjs runNavigationLoop, after waitForKey():
if (action === 'copy') {
  // Flash message, then re-render after delay
  process.stdout.write(clearScreen());
  process.stdout.write(style('  Copied to clipboard', 'green', 'bold') + '\n');
  await new Promise(r => setTimeout(r, 1500));
  // Loop continues, re-renders current lesson
}
```

### Anti-Patterns to Avoid
- **Do NOT strip ANSI from rendered output:** The renderer produces ANSI-encoded strings. Instead, format directly from the lesson data object (JSON), bypassing the renderer entirely. This is cleaner and avoids regex ANSI stripping edge cases.
- **Do NOT use async clipboard writes with callbacks:** Use `execSync` for clipboard so the flash message timing is predictable.
- **Do NOT import the full renderer in the formatter:** The formatter is a separate pure function that works with the raw lesson JSON data, not rendered ANSI strings.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| ANSI stripping | Regex to remove ANSI codes | Format from raw lesson JSON directly | ANSI regex is fragile; raw JSON is the source of truth |
| Clipboard detection | Custom platform sniffing | `process.platform` switch | Node.js provides this; three values cover all cases |
| Temp file cleanup | Manual cleanup logic | OS temp directory (auto-cleaned) | `os.tmpdir()` files are ephemeral by convention |

**Key insight:** The lesson data is available as a structured JSON object. Converting JSON to markdown is trivial and reliable. Converting ANSI-rendered terminal output back to clean markdown is fragile and unnecessary.

## Common Pitfalls

### Pitfall 1: Windows `clip` command encoding
**What goes wrong:** `clip` on Windows expects UTF-16LE input by default, but `execSync` sends UTF-8. Non-ASCII characters (like box-drawing chars in concept map) may get garbled.
**Why it happens:** Windows clipboard has encoding expectations different from Unix tools.
**How to avoid:** Test with the actual concept map content. `clip` in modern Windows 10/11 handles UTF-8 from stdin pipe correctly in most cases. If issues arise, pipe through `powershell -command "Set-Clipboard -Value (Get-Content -Raw -Encoding UTF8)"` as alternative.
**Warning signs:** Garbled characters in pasted output on Windows.

### Pitfall 2: Flash message and raw mode interaction
**What goes wrong:** Writing to stdout while stdin is in raw mode can cause display issues.
**Why it happens:** The keypress handler sets raw mode; flash message writes happen between keypress resolution and next render.
**How to avoid:** The current `waitForKey()` already exits raw mode and pauses stdin in `cleanup()` before resolving. The flash message happens after cleanup, so this should work correctly. Verify in testing.
**Warning signs:** Garbled terminal output after pressing 'c'.

### Pitfall 3: xclip not installed on Linux
**What goes wrong:** `execSync('xclip ...')` throws ENOENT or returns error.
**Why it happens:** xclip is not installed by default on many Linux distributions.
**How to avoid:** The fallback-to-file mechanism handles this. Also consider trying `xsel --clipboard --input` as a second attempt before falling back to file. Include helpful error message mentioning `sudo apt install xclip`.
**Warning signs:** Error on first 'c' press on a fresh Linux install.

### Pitfall 4: execSync hanging on Linux without X11
**What goes wrong:** xclip requires an X11 display. On headless/SSH sessions, it hangs indefinitely.
**Why it happens:** xclip waits for X11 connection.
**How to avoid:** Set a timeout on execSync: `execSync(cmd, { input: text, timeout: 3000 })`. Three seconds is generous; clipboard write should be instant.
**Warning signs:** Terminal freezes after pressing 'c' in SSH session.

## Open Questions

1. **Should the formatter handle the concept map "YOU ARE HERE" marker?**
   - What we know: `renderConceptMap()` adds a marker based on `lesson.conceptMap` string (e.g., "tool-dispatch"). The raw `CONCEPT_MAP` constant is the base diagram.
   - What's unclear: Should the clipboard version include the marker or just the base diagram?
   - Recommendation: Include the marker -- it provides context about where the lesson fits. Use the same `renderConceptMap()` logic but strip ANSI from its output, OR replicate the marker insertion in plain text. Given the simplicity, replicating is cleaner.

2. **Should `wl-copy` be supported as a Wayland alternative to xclip?**
   - What we know: Wayland is increasingly common on Linux. `xclip` requires X11.
   - What's unclear: How many GSD users run Wayland without XWayland.
   - Recommendation: Try `xclip` first, then `xsel`, then `wl-copy`, then fallback to file. Or keep it simple with just `xclip` + file fallback per user decision. Claude's discretion area.
