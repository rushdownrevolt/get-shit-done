# Phase 01.1: Block-based lesson display with per-block navigation and module progress tracker - Context

**Gathered:** 2026-03-12
**Status:** Ready for planning

<domain>
## Phase Boundary

Break lessons into manageable "parts" (one content section per screen), replace the current all-at-once rendering with part-by-part navigation, add a dot-based progress tracker, redesign navigation shortcuts, and show a celebratory banner when a module is 100% complete. Retroactively applies to all existing lessons with no JSON changes needed.

</domain>

<decisions>
## Implementation Decisions

### Block boundaries
- Each content section in the lesson JSON `content` array becomes one "part"
- One part displayed per screen — user advances with 'w'
- No JSON schema changes — renderer splits existing content array
- No changes to lesson generation pipeline — content arrays are already properly sectioned

### Part display
- Subtle but descriptive block headers on each part (e.g., dim label describing the content type/topic)
- Objective ("What you'll learn") pinned as fixed header on every part
- Success criteria ("You'll know you got it when") pinned as fixed footer on every part
- Concept map placement: Claude's discretion

### Progress tracker
- Dot indicator style: ● ● ● ○ ○ ○ ○ ○ ○  Part 3 of 9
- User-facing terminology: "Part" (not "block" or "section")
- Positioned at bottom, above the navigation shortcuts footer
- Shows current position within the lesson's parts

### Navigation shortcuts (redesigned)
- `w` — Next part (replaces `n`)
- `q` — Previous part (replaces `p`; was quit)
- `e` — Skip to next lesson (first part of next lesson)
- `c` — Copy lesson to clipboard (unchanged)
- `esc` — Quit (replaces `q` quit behavior)
- Arrow keys: removed or remapped to match new scheme

### Module completion announcement
- Colorful banner with stats when user completes the last part of the last lesson
- Shows: module name, lessons count, parts count, mini-project count
- Triggered after pressing 'w' on the final part of the final lesson
- Style: solid color bars top/bottom, "MODULE COMPLETE!" centered, stats below

### Retrofit strategy
- Auto-derive parts from existing content array — no JSON edits needed
- Renderer change only — existing lessons work immediately
- Future lessons also require no changes (same JSON format)

### Claude's Discretion
- Concept map placement (own part vs pinned)
- Exact block header wording/styling for each content type
- Color choices for progress dots and completion banner
- Whether arrow keys are kept as aliases for w/q

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `renderer.cjs:renderLesson()`: Pure function returning ANSI string — needs refactoring to render single parts instead of full lesson
- `navigator.cjs:waitForKey()`: Keypress handler — needs new key mappings (w/q/e/esc)
- `navigator.cjs:runNavigationLoop()`: Main loop — needs inner part-navigation loop within lesson navigation
- `terminal.cjs:style()`: ANSI styling — reuse for progress dots and completion banner
- `progress.cjs`: Tracks lesson-level progress — may need part-level tracking

### Established Patterns
- Navigator uses single-key keypresses via readline keypress events — new keys follow same pattern
- Renderer is a pure function returning string — maintain this for testability
- Lessons loaded as JSON with typed content array (text/code/project sections)

### Integration Points
- `navigator.cjs:runNavigationLoop()` — main loop needs part-level navigation state
- `renderer.cjs:renderLesson()` — refactor to `renderPart()` or add part index parameter
- `gsd-learn.cjs` — entry point may need module completion detection
- `clipboard-formatter.cjs` — still copies full lesson (not just current part)

</code_context>

<specifics>
## Specific Ideas

- User wants this specifically to prevent content from spilling over a typical terminal window
- More "next" presses = more feeling of progress (psychological benefit)
- Less intimidating for new users — smaller chunks are more approachable
- The progress dots + "Part X of Y" gives clear orientation within the lesson
- Navigation footer preview: `[w] Next  [q] Back  [e] Skip lesson  [c] Copy  [esc] Quit`

</specifics>
