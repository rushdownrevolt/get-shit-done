Idea -> /gsd:kickoff

Block 3 (text): Walk through a concrete example. Imagine you're building a CLI tool. You run /gsd:kickoff, which creates PROJECT.md capturing your core value ("fast file search"). From PROJECT.md, /gsd:requirements creates REQUIREMENTS.md with REQ-IDs like SEARCH-01, SEARCH-02. From requirements, /gsd:roadmap creates ROADMAP.md grouping them into phases: Phase 1 (index engine), Phase 2 (query parser), Phase 3 (CLI interface). Each requirement traces to exactly one phase.

Block 4 (text): Continue the example into execution. Phase 1 starts: /gsd:plan-phase creates PLAN.md with 2 tasks (create index data structure, implement file walker). /gsd:execute-phase runs both tasks, producing SUMMARY.md recording what was built, decisions made, and patterns established. STATE.md updates: "Phase 1 of 3, 2/2 plans complete." Phase 2 follows the same cycle. After Phase 3, all requirements are met.

Block 5 (text): Continue into milestone completion. You run /gsd:complete-milestone. It creates a MILESTONES.md entry with stats (3 phases, 6 plans, 18 tasks, 4 days). It archives ROADMAP.md and REQUIREMENTS.md to milestones/v1.0-ROADMAP.md and v1.0-REQUIREMENTS.md. It evolves PROJECT.md — moving shipped requirements to Validated, updating context with current state. It creates a git tag v1.0. It writes RETROSPECTIVE.md capturing what worked and what didn't. The project is now ready for v1.1.

Block 6 (text): The key pattern — artifact persistence. Every GSD artifact solves the same fundamental problem: context loss. PROJECT.md persists the "why" across the entire project lifetime. REQUIREMENTS.md persists the "what" within a milestone. ROADMAP.md persists the "when and order." PLAN.md persists the "how" for each phase. SUMMARY.md persists "what actually happened." STATE.md persists "where we are right now." MILESTONES.md persists "where we've been." RETROSPECTIVE.md persists "what we learned." Without these artifacts, every new session starts from zero.
