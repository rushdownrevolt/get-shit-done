<feature>
  <name>GSD Markdown Parser</name>
  <files>learn/lib/markdown-parser.cjs, learn/lib/frontmatter.cjs, learn/tests/markdown-parser.test.cjs</files>
  <behavior>
    **extractFrontmatter (local copy):**
    - Input: string content with ---\nYAML\n--- header
    - Output: JS object of key-value pairs
    - Handles: simple values, inline arrays, list arrays, nested objects

    **parseMarkdownFile(filePath):**
    - Command spec with frontmatter -> fileType: 'command-spec', frontmatter populated, sections: { objective, execution_context, process }
    - Workflow without frontmatter -> fileType: 'workflow', frontmatter: {}, sections: { purpose, process }
    - File with @file: references -> fileReferences: ['path1', 'path2']
    - File with @C:/path references -> fileReferences: ['C:/path'] (Windows absolute paths)
    - File with fenced code blocks -> codeBlocks: [{ language: 'bash', code: '...' }]
    - File with code block without language -> codeBlocks: [{ language: null, code: '...' }]
    - Duplicate XML section tags (e.g., multiple step tags) -> section value becomes array
    - body field contains everything after frontmatter (or full content if no frontmatter)
    - Missing file throws descriptive error

    **fileType detection:**
    - Has YAML frontmatter (starts with ---) -> 'command-spec'
    - No frontmatter -> 'workflow'
  </behavior>
  <implementation>
    **Step 1: Create learn/lib/frontmatter.cjs**
    - Copy the pure `extractFrontmatter(content)` function (~80 lines) from `get-shit-done/bin/lib/frontmatter.cjs`
    - Do NOT import from get-shit-done/ (keeps learn/ self-contained per RESEARCH.md recommendation)
    - Export only `{ extractFrontmatter }`

    **Step 2: Create learn/lib/markdown-parser.cjs**
    - Require: fs, path, and local ./frontmatter.cjs
    - `parseMarkdownFile(filePath)` reads file, detects type, extracts all components
    - `extractXmlSections(content)` uses non-greedy regex `<(\w+)>([\s\S]*?)<\/\1>` for named map; handles duplicate tags by converting to array
    - `extractFileReferences(content)` matches `@([^\s<>]+)` and filters to file-like refs (contain / or \ or .)
    - `extractCodeBlocks(content)` matches fenced code blocks with optional language
    - fileType detection: has frontmatter -> 'command-spec', else -> 'workflow'
    - body: content after frontmatter separator, or full content if no frontmatter
    - Export `{ parseMarkdownFile }`

    **Anti-patterns to avoid:**
    - Do NOT use greedy regex with dotall for XML sections (Pitfall 4 from RESEARCH.md)
    - Do NOT import from get-shit-done/bin/lib/ (Pitfall 3 from RESEARCH.md)
    - Do NOT make this a general-purpose parser -- scoped to command specs and workflows only
  </implementation>
</feature>
