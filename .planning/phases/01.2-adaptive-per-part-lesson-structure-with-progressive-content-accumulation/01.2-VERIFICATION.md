### Human Verification Required

#### 1. Visual rendering of progressive accumulation

**Test:** Run `node learn/bin/gsd-learn.cjs` from the project root. Navigate Lesson 1 and press 'w' multiple times.

**Expected:**
- Part 1: One block with focus line showing `▶ <focus text>` and a bridge section in a bordered Unicode box
- Part 2: Two blocks accumulated — block 1 focus has NO marker (indented dim), block 2 focus HAS the `▶` marker; dim horizontal rule separates the blocks; both bridge sections visible
- 'q' to go back: screen shrinks to previous part (fewer blocks)
- Last part of any lesson: success criteria ("You'll know you've got it when:") appears; objective ("What you'll learn:") does NOT appear
- First part only: objective appears; success criteria does NOT appear

**Why human:** ANSI styling is a visual/experiential property. In the test runner (non-TTY), `style()` is a no-op — the triangle, colors, and box-drawing characters render correctly only in a real terminal. The structural tests pass, but actual visual confirmation is required.

#### 2. Focus and bridge content quality review (GEN-02 quality component)

**Test:** Run `node learn/bin/gsd-learn.cjs`, navigate through Lessons 1-3, and read the focus lines and bridge sections.

**Expected:**
- Focus phrases are 3-8 words that clearly describe what each specific block teaches (not just truncated first sentences)
- Bridge sentences create narrative flow — each bridge should make the reader want to continue to the next block
- The last block in each lesson references the next lesson title in its bridge text (e.g., "Next up: Where Commands Start")
- Lesson 6 final bridge references module completion rather than a next lesson

**Why human:** Content quality is subjective. The texts pass structural validation (non-empty strings), but whether they are pedagogically effective requires reading them in context.
