  <action>
    Write tests first (RED), then implement (GREEN), then refactor if needed.

    The renderer is a pure-function module with zero dependencies beyond Node.js builtins. It takes parsed JSON objects and returns markdown strings.

    Key design decisions:
    - Export individual render functions AND a top-level renderModule that composes them
    - renderModule accepts all data (module.json, sorted lessons[], spec.json, hints[], concept-map.txt string) and returns complete markdown
    - Lessons are rendered in lessonNumber order
    - The mini-project lesson (lessonNumber matching the last lesson, typically titled "Mini-Project: ...") is SKIPPED in the lessons section because the project spec + hints sections replace it
    - Text blocks: render value only (focus and bridge are interactive-mode metadata, not for static docs)
    - Code blocks: use triple-backtick fences with language annotation from the `language` field
    - Project spec: render each artifact with its checks as a markdown checklist (- [ ] description)
    - Hints: render as numbered details/summary HTML blocks for progressive disclosure
    - Concept map: wrap the raw ASCII text in a plain code fence
    - All functions are synchronous (pure string transforms)

    File structure for markdown-renderer.cjs:
    ```
    renderContentBlock(block) -> string
    renderLesson(lesson) -> string
    renderProjectSpec(spec) -> string
    renderHints(hints) -> string
    renderConceptMap(text) -> string
    renderModule(module, lessons, spec, hints, conceptMapText) -> string
    ```
