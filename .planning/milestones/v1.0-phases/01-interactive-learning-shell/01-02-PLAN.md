<task type="auto">
  <name>Task 2: CLI entry point wiring everything together</name>
  <files>learn/bin/gsd-learn.cjs</files>
  <action>
Create `learn/bin/gsd-learn.cjs` with hashbang `#!/usr/bin/env node` and 'use strict'.

The entry point:

1. Parse CLI args from process.argv.slice(2). Support flags: `--reset` (clear progress), `--status` (show progress summary), `--module=NAME` (select module, default 'command-lifecycle'). Use simple loop parsing (no library).

2. Validate environment using errors.cjs validateEnvironment(process.cwd()). If invalid, print the error message to stderr and exit(1).

3. If `--reset`: delete progress file via fs.unlinkSync (with try/catch), print confirmation, exit(0).

4. If `--status`: load progress, print current module and lesson position, exit(0).

5. Default (start/resume learning):
   a. Load progress via progress.cjs loadProgress(cwd)
   b. Load module via lessons.cjs loadModule(moduleId, contentDir)
   c. Determine startIndex from progress (progress.currentLesson or 0)
   d. Call navigator.cjs runNavigationLoop with:
      - renderFn: calls renderer.cjs renderLesson, writes result to process.stdout
      - progressFn: updates progress object and calls saveProgress
   e. On loop exit (quit), print goodbye message

6. Wrap the entire main flow in try/catch. On error, call errors.cjs formatError and write to stderr, then exit(1). This ensures no stack traces reach the user (PROG-02).

Match the entry point pattern from 01-RESEARCH.md (CLI Entry Point section).
  </action>
  <verify>
    <automated>node learn/bin/gsd-learn.cjs --status 2>&1 || true</automated>
  </verify>
  <done>
    - gsd-learn.cjs exists with hashbang
    - Running from GSD repo root with --status prints progress info
    - Running from wrong directory prints helpful error (not stack trace)
    - --reset clears progress file
    - Default mode launches interactive lesson navigation
  </done>
