<objective>
Implement content grouping so code/diagram blocks merge with adjacent text into single rendered "parts", update focus/bridge to be per-group, update all lesson JSONs across both modules, and update navigator totalParts calculation.

Purpose: Code snippets and diagrams appearing alone with no surrounding text are disorienting. The grouping rule ensures a code block always appears with its lead-in text and explanation, forming a coherent unit. This changes what a "part" means: from individual content items to logical groups.

Output: groupContentItems() function in renderer.cjs, updated renderPart to iterate groups, updated navigator.cjs totalParts, updated validation in lessons.cjs, updated all 12 lesson JSONs (6 command-lifecycle + 6 gsd-commands), updated tests.

    **Step 1: Create groupContentItems() in renderer.cjs**

    Add a new exported function `groupContentItems(contentArray)` that transforms a flat content array into an array of groups:

    ```javascript
    function groupContentItems(content) {
      const groups = [];
      let current = null;

      for (const item of content) {
        if (item.type === 'code') {
          // Code block: attach to current group if one exists, otherwise start a new group
          if (current) {
            current.items.push(item);
          } else {
            // Code block at start with no preceding text -- start a new group
            current = { items: [item], focus: item.focus || '', bridge: item.bridge || '' };
          }
        } else {
          // Text or project block: finalize previous group (if any), start new group
          if (current) {
            groups.push(current);
          }
          current = { items: [item], focus: item.focus, bridge: item.bridge };
        }
      }
      if (current) groups.push(current);

      // Post-process: absorb trailing text into code groups when the code block starts a group
      // Actually, per the CONTEXT decision: "lead-in text + code/diagram + explanation text = one combined part"
      // The above logic already handles this: text starts group, code attaches to it.
      // Edge case: if a code block starts the content array, it becomes its own group (acceptable fallback).

      return groups;
    }
    ```
