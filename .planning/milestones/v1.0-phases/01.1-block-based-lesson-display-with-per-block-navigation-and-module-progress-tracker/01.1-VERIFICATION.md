### Implementation Notes (vs. Plan Spec)

The plan specified "pinned objective/criteria footer on every part." The implementation evolved to:
- **Objective:** shown only on part 0 (first screen of a lesson)
- **Success criteria:** shown only on the last part

This is a deliberate design evolution (progressive accumulation model), tested explicitly, and does not undermine the phase goal. The user still sees the objective at the start of each lesson and the criteria before moving on — the goal intent is preserved.

The navigation footer includes `[m] Modules` beyond what the plan specified — an additive enhancement from a later phase, not a deficit.

`renderProgressDots` exists and is tested but is not called by `renderPart` in the final implementation. Part position is tracked via `renderLessonProgressFooter` (module-level progress bar). The function is available for external use and satisfies the export contract.
