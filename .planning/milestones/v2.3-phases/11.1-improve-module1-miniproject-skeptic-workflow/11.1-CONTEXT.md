<decisions>
## Implementation Decisions

### Template delivery
- Provide the REAL GSD skeptic workflow (from ~/.claude/get-shit-done/workflows/skeptic.md) as a starting template
- Deliver via clipboard copy — show the workflow in the lesson content, learner presses C to copy, then pastes into the file they create
- Only the WORKFLOW file is templated — learner still writes the command spec (skeptic.md) from scratch
- The command spec remains the core structural challenge; the workflow template shows what a real GSD workflow looks like

### Creative freedom
- Open-ended customization: "make it your own" with no specific constraints
- Learners can rewrite critique logic, add/remove steps, reorder process, change the voice — whatever they want
- The template is a starting point and reference, not a fill-in-the-blanks exercise
- Verification only checks structural minimum, not that they kept template content

### Verification approach
- Keep current minimal checks: <purpose> and <process> sections only
- Do NOT add checks for <step> elements, success_criteria, or template-specific patterns
- Maximizes creative freedom — learner can restructure the workflow completely
- Module 2 spec.json carries Module 1 checks forward (cross-module spec pattern) — those stay unchanged too

### Claude's Discretion
- Exact lesson text changes to introduce the template and clipboard copy workflow
- How to word the "make it your own" encouragement
- Whether hints need rework given the template approach (currently assume building from scratch)
- How much of the workflow to show inline vs what requires clipboard copy

</decisions>

<specifics>
## Specific Ideas

- The user specifically wants learners to see the REAL skeptic workflow they created — authentic content, not a synthetic example

- The template approach shifts the pedagogical model: from "figure out the structure" to "learn from a working example, then customize"
