### Phase 1: Interactive Learning Shell
**Goal**: Learner can launch the CLI, navigate through hand-written lessons with readable formatting, and resume where they left off across sessions
**Depends on**: Nothing (first phase)
**Requirements**: DISP-01, DISP-02, DISP-03, CONT-01, CONT-02, PROG-01, PROG-02, PROG-03
**Success Criteria** (what must be TRUE):
  1. Learner can run `gsd-learn` and see a formatted lesson with ANSI colors, code blocks, and inline GSD source code
  2. Learner can navigate forward/backward through numbered lessons and see their position ("Lesson N of M")
  3. Learner can quit, reopen the tool, and resume at the exact lesson where they left off
  4. Learner sees an ASCII concept map showing where the current lesson fits in GSD's architecture
  5. Learner sees a helpful error message (not a stack trace) when running from the wrong directory or with missing files
**Plans**: 2/2 complete

### v2.0 GSD Commands & Workflows Module

### Phase 4: Multi-Module Infrastructure
**Goal**: gsd-learn can host multiple modules with correct per-module progress tracking, filesystem-driven concept maps, tilde path resolution, and a markdown parser ready to feed lesson generation
**Depends on**: Phase 3 (v1.0 complete)
**Requirements**: INFRA-01, INFRA-02, INFRA-03, INFRA-04, PIPE-01, PIPE-02, PIPE-03, MOD2-01
**Success Criteria** (what must be TRUE):
  1. Learner's existing Command Lifecycle progress is preserved after upgrading — v1 progress auto-migrates to v2 per-module schema with no data loss
  2. gsd-learn starts in Module 1 Lesson 1 by default, and Command Lifecycle appears as Module 2 (via order field, ID unchanged)
  3. Concept map loads its diagram from module-owned definitions — each module defines its own concept map content
  4. Verifier correctly resolves `~/` paths to the user's home directory for artifact checks
  5. Markdown parser extracts frontmatter, XML sections, code blocks, and file references from real GSD .md files — and prompt templates use generic `{{KEY}}` replacement
**Plans**: 3 plans

Plans:
- [ ] 04-01-PLAN.md — Infrastructure: progress migration, concept maps, verifier tilde expansion, module ordering
- [ ] 04-02-PLAN.md — Markdown parser for command specs and workflows
- [ ] 04-03-PLAN.md — Generic template system and markdown-anatomy prompt

### Phase 5: Module 1 Lessons
**Goal**: Learner can navigate through 5 teaching lessons (overview + 4 dives + bridge) that explain how GSD slash commands and workflows work, built from parsed markdown source files
**Depends on**: Phase 4
**Requirements**: MOD1-01, MOD1-02, MOD1-03, MOD1-04, MOD1-06
**Success Criteria** (what must be TRUE):
  1. Learner can start Module 1 and see a conceptual overview of GSD's two-layer architecture (command.md dispatches to workflow.md)
  2. Learner can navigate through anatomy lessons that show real command.md and workflow.md source with highlighted sections (frontmatter, XML, process steps, code blocks)
  3. Learner can see how a `/gsd:X` command dispatches through the full chain from command spec to workflow execution
  4. Learner sees a bridge lesson at the end that previews Module 2's Node.js layer, connecting what they learned to what comes next
**Plans**: TBD

### Phase 6: Module 1 Mini-Project
**Goal**: Learner completes a capstone project building a custom command.md + workflow.md pair, with structural verification and progressive hints
**Depends on**: Phase 5
**Requirements**: MOD1-05, MOD1-07, MOD1-08
**Success Criteria** (what must be TRUE):
  1. Learner can build a custom command.md and workflow.md pair as their mini-project, guided by clear instructions
  2. Learner can run verification that structurally checks their markdown artifacts (frontmatter fields, XML sections, file references) without requiring exact content matches
  3. Learner can request progressive hints (5 levels) that guide from conceptual reframe to step-by-step without giving away the answer

**Plans**: TBD
