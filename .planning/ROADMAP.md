# Roadmap: GSD Learn

## Overview

GSD Learn delivers a terminal-based interactive learning tool that teaches the GSD codebase through prompt-generated lessons and validated mini-projects. The roadmap follows a validate-before-automating strategy: first build a working interactive shell with hand-written content to prove the teaching model works, then build a prompt engineering pipeline that generates quality lessons from GSD source (with evaluation criteria to iterate on prompt quality), and finally add the mini-project validation layer that proves real learning happened. Each phase delivers a usable, testable artifact.

## Phase Details

### Phase 1: Interactive Learning Shell
**Goal**: Learner can launch the CLI, navigate through hand-written lessons with readable formatting, and resume where they left off across sessions
**Depends on**: Nothing (first phase)
**Requirements**: DISP-01, DISP-02, DISP-03, CONT-01, CONT-02, PROG-01, PROG-02, PROG-03
**Success Criteria** (what must be TRUE):
  1. Learner can run `gsd-learn` and see a formatted lesson with ANSI colors, code blocks, and inline GSD source code
  2. Learner can navigate forward/backward through numbered lessons and see their position ("Lesson N of M")
  3. Learner can quit, reopen the tool, and resume at the exact lesson where they left off
  4. Learner sees an ASCII concept map showing where the current lesson fits in GSD's architecture
  5. Learner sees a helpful error message (not a stack trace) when running from the wrong directory or with missing files
**Plans**: 2 plans

Plans:
- [ ] 01-01-PLAN.md — Foundation modules: terminal utilities, progress persistence, lesson data model, concept map, and 5 hand-written lessons
- [ ] 01-02-PLAN.md — Integration: renderer, navigator, error handling, CLI entry point, and end-to-end verification

### Phase 2: Prompt-Driven Content Pipeline
**Goal**: Lessons are generated by prompts that take parsed GSD source as input, with evaluation criteria that let us measure output quality and iterate on prompts until lessons are good enough
**Depends on**: Phase 1
**Requirements**: CONT-03, CONT-04, CONT-05, MODL-01, MODL-02
**Success Criteria** (what must be TRUE):
  1. A source parser extracts relevant code, exports, and structure from GSD files and feeds them as context to lesson-generation prompts
  2. Prompts produce lesson content that includes actual GSD source code with "why" explanations -- not just code dumps or generic descriptions
  3. An evaluation rubric exists that scores prompt outputs on criteria like accuracy, clarity, appropriate depth, and connection to the concept map
  4. At least one round of prompt iteration has occurred where evaluation results drove specific prompt changes that measurably improved output
  5. The Command Lifecycle module has a conceptual overview lesson and source-code deep-dive lessons, all generated through the prompt pipeline
**Plans**: 2 plans

Plans:
- [ ] 02-01-PLAN.md — Source parser and prompt templates: TDD-built parser for GSD CommonJS files and two prompt template types (overview, source-dive)
- [ ] 02-02-PLAN.md — Evaluator, pipeline, and lesson generation: rubric scoring module, pipeline script, and generation of all 5 Command Lifecycle lessons with quality evaluation

### Phase 3: Mini-Project Validation
**Goal**: Learner completes a capstone mini-project that proves real capability, with progressive hints when stuck and feedback data that measures lesson quality
**Depends on**: Phase 2
**Requirements**: VALD-01, VALD-02, VALD-03, VALD-04, MODL-03, MODL-04
**Success Criteria** (what must be TRUE):
  1. Learner can run a verify command that checks whether their mini-project is structurally complete (produced a real GSD artifact, not exact code matching)
  2. Learner can request hints when stuck, receiving progressive nudges that guide without giving answers
  3. The Command Lifecycle module ends with a mini-project where the learner uses GSD to build something real
  4. Time-to-complete, hints used, and verification attempts are tracked to a local file for assessing lesson effectiveness
**Plans**: 3 plans
